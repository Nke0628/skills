# ウィザード

**ウィザード**とは、自分で行うには面倒で、その都度AIに説明するのも面倒な手作業の手順を、人間に一歩ずつ案内するbashスクリプトである。各URLを開き、何をクリックしコピーすべきかを正確に伝え、値を取得し、それらを然るべき場所（`.env`、GitHub secrets）に書き込み、各ステージで確認を取り、残りのステージ数を示す。サードパーティサービスの設定、一回限りの移行の実行、プロジェクトをある状態から別の状態へ移す作業などに使われる。

快適なUXはすでに[template.sh](template.sh)で解決済みである。ステージごとの進捗表示、確認ゲート、クロスプラットフォームのURLオープン（WSLを含む）、シークレット入力の非表示、`.env`への冪等なupsert、`gh secret`/`gh variable`への書き込み、締めくくりのサマリー表示など。**あなたの仕事は手順のスコープを決め、そのステージを作成することだけである。** `STAGES`マーカーより上のライブラリはすべてのウィザードで同一である。その一貫性こそが要点であり、手で編集してはならない。

ウィザードはデフォルトでは一時的なものである。一回の実行のために作られ、スクラッチや`scripts/`パスに保存され、作業が終わったら削除される。ユーザーがリポジトリに残る再利用可能なセットアップ手順を望む場合にのみコミットする。

## プロセス

### 1. 手順のスコープを決める

人間が取るべきすべての手作業のステップと、その過程で取得されるすべての値を洗い出す。いきなり質問するのではなく、まずリポジトリを読むこと。

- セットアップの場合: `.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、フレームワークの設定、`.github/workflows/*`（`secrets.*` / `vars.*`への参照はすべて、ウィザードが生成すべき値である）。
- 移行や移行作業の場合: 現在の状態、目標の状態、その間にある不可逆なアクション。

その後、ステージの順序付きリストと各ステージが生成する値をユーザーに示し、確認を取る。ユーザーは追加・削除・並べ替えができる。

**完了の目安:** すべてのステージが順番に名付けられており、取得する各値について (a) 人間がどこでそれを取得するか、(b) それがどこに書き込まれるか（`.env`、GitHub secret、両方、あるいはどこにも書き込まれない純粋なアクションのステージもある）、(c) それが秘密情報か（非表示入力）公開情報かがわかっている状態。

### 2. 各ステージの経路をマッピングする

各ステージについて、人間がたどる正確な経路を書き出す。どのURLを開くか、そこで何をするか、どこに値が表示されるか、それがどの変数に入るか、といった具合に。例: 「ダッシュボード → Developers → API keys → Reveal test key → コピー」。現在のUIや正確なコマンドを実際には知らない場合は、その旨を伝えてユーザーに確認するか、ドキュメントを確認すること。存在するかどうかわからないステップを創作してはならない。

**完了の目安:** すべてのステージが、見知らぬ人でも従える具体的な指示にたどり着いている状態。

### 3. ウィザードを作成する

`template.sh`を目的のパスにコピーする。サンプルのステージを、依存関係の順に沿った`stage`ごとの記述に置き換える。ライブラリのヘルパーを使う: `stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。書いたステージ数に`TOTAL_STAGES`を設定する。

テンプレートが定める基準を守ること: 値を尋ねる前にURLを開く、秘密情報には`ask_secret`を使う、永続化する値はすべて`write_env`する、CIが実際に必要とする値だけを`set_secret`する、不可逆なアクションの前には`confirm`する。各`stage`は画面をクリアするので、現在のステージだけが表示される。人間に必要な情報がスクロールで消えないよう、1ステージにつき1つの作業に絞ること。マーカーより上のライブラリには触れないこと。

### 4. 検証して引き渡す

- `bash -n <script>`を実行し、可能であれば`shellcheck`も実行する。
- `chmod +x <script>`を実行する。
- 最後まで自分で実行してはならない。ブラウザを開き、人間の入力でブロックされるためである。代わりに静的にトレースすること。ステップ1で挙げたすべての値が取得され、ステップ1で指定した場所に格納されているか、そしてすべての`set_secret`の名前がCI内の`secrets.*`参照と正確に一致しているかを確認する。
- 実行方法をユーザーに伝える。再利用可能なセットアップ手順であれば、コミットしてREADMEからリンクし、次の人がAIに尋ねる代わりにスクリプトを実行できるようにする。
