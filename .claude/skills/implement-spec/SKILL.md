仕様書が渡されている。この仕様書には、それをどう実装するかを説明する関連チケットがあるはずだ。

目標は、単一のブランチ上で仕様全体を実装する1つのPRを作ることだ。

チケットは手順のリストではない。それらはブロッキング関係を持つ**タスクグラフ**である。つまり、常に着手可能なチケットの**フロンティア**が存在する。

サブエージェントとのやり取りは最小限に抑える。主に**コンテキストポインタ**を通じてコミュニケーションする: 仕様書、チケット、リサーチノート、過去のコミットへのポインタだ。ポインタ経由で参照できる情報を重複させないこと。

**実装サブエージェント**は、**最大限の並行性**を得るため、可能な限りバックグラウンドで実行すべきだ。

## 手順

1. 仕様書とチケットを読む。タスクグラフを理解できる程度に読み込む。

2. (任意)チケットに必要な調査 - 関連するコードベースのファイルや外部ドキュメント - を行うために**探索サブエージェント**を使う。探索サブエージェントがファイルを保存できるようにすること。そのMarkdownノートは、以後のすべてのサブエージェントがアクセスできる、リポジトリ外のディレクトリに保存すべきだ。これにより、**実装サブエージェント**は探索ではなく実装に集中できる。

3. ブランチとドラフトPRを作成する。このPRは仕様のissueとチケットを「closing(クローズ)」する形でマークすべきだ。

4. 各チケットの実装には**実装サブエージェント**を使う。各実装サブエージェントは、それぞれ独自のworktreeで独自のブランチ上で作業すべきだ。

5. **実装サブエージェント**が完了したら、**マージサブエージェント**を使ってその作業をPRブランチにマージする。

6. これにより着手可能なチケットの**フロンティア**が変化する場合、新しいチケットに取り組む**実装サブエージェント**をさらに起動する。これにより最大限の並行性が得られる。

7. 全チケットが完了したら、PRブランチに対して/code-reviewを実行する。コードレビューで指摘されたすべての問題を、単一の**実装サブエージェント**で修正する。

8. PRをレビュー可能状態としてマークする。

9. すべての**実装サブエージェント**のworktreeをクリーンアップする。
