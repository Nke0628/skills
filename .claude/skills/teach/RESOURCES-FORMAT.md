# RESOURCES.md Format

`RESOURCES.md`は、このトピックについて信頼できる情報源を厳選したものである。解説の知識はパラメトリックな推測からではなく、ここから引き出すべきである。知恵はここに挙げたコミュニティから得られる。

## 構造

```md
# {トピック} Resources

## Knowledge

- [Book: _The Science and Practice of Strength Training_ by Zatsiorsky & Kraemer](https://example.com)
  プログラミングと適応に関する基礎文献。用途: 期分け、回復、強度ゾーンに関することすべて。
- [Article: "How Much Should I Train?" by Greg Nuckols (Stronger By Science)](https://example.com)
  ボリュームの目安に関するエビデンスベースのレビュー。用途: 筋群ごとの週間セット数の目標。

## Wisdom (Communities)

- [r/weightroom](https://reddit.com/r/weightroom)
  シグナル比の高いsubreddit。エセ科学が入り込まないようモデレートされている。用途: プログラム批評、プラトー(停滞期)のトラブルシューティング。
- Local: {ジム名}での火曜日の筋力トレーニングクラス
  用途: リフトへのリアルタイムなコーチングフィードバック。
```

## ルール

- **信頼度の高いものだけ。** 一次情報源、名の知れた専門家、査読済みの研究、そして強くモデレートされたコミュニティを優先する。教育を装ったマーケティングであれば除外すること。
- **すべてのエントリに注釈を付ける。** 裸のリンクは3か月後には使い物にならない。何をカバーしていて、いつ頼るべきかを1行で添えること。
- **KnowledgeとWisdomでグループ化する。** [SKILL.md](./SKILL.md)の方針を反映している。あるリソースが片方のグループにしか現れなくても構わない。
- **ギャップを明示的に示す。** ミッションが必要としている領域に良いリソースが存在しない場合、`## Gaps`セクションを書いて何が欠けているかを列挙する。これが今後の検索を駆動する。
- **容赦なく刈り込む。** 間違っていた、浅かった、あるいはミッションから外れていたと分かったリソースは、埋もれさせるのではなく削除すること。30の平凡な情報源より、5つの鋭い情報源の方がよい。
- **コミュニティに関する意向を記録する。** ユーザーがコミュニティに参加しないと決めている場合はここに記録し、以降のセッションで繰り返し提案しないようにする。
