# apply: 人の調整を反映する

人の調整は3種類が混ざって届く。全部を取り込み、波及先を確認し、追加の質問を出す。フェーズ内で何周してもよい。

## 手順

### 1. 取り込む

1. **直接編集:** `git status --porcelain docs/rdra` で未コミットの編集があれば、`git diff docs/rdra` を読んでから `rdra: 人の編集を取り込み` としてコミットする。前回の `rdra:` コミット以降に人がコミットした変更も `git log` / `git diff <前回のrdraコミット>..HEAD -- docs/rdra` で確認する。
2. **質問への回答:** `rdra.py merge-answers` を実行する(answers.json → questions.md の回答・状態)。「反映済から回答が変わった」と出たIDは、再反映の対象にする。
3. **追加資料:** `docs/rdra/inputs/` に前回以降に追加・変更されたファイルを読む(git の差分で判定)。

### 2. 成果物に反映する

**回答済の質問**ごとに:
- 回答が提案どおり → 質問列にそのIDを持つ仮説の行を `回答` にし、質問列からIDを消す。
- 質問列にそのIDを持つ行がない(`要望` / `資料` / `回答` の行を対象にした質問。review などで出る)→ `対象:` に書かれた要素を表から探し、回答に合わせて書き換えて `回答` にする。回答が「今のままでよい」なら行は変えない。
- 回答が提案と違う → 回答に合わせて行を書き換え、`回答` にする。削除の指示なら削除する(人の判断による削除なのでよい)。
- 回答が曖昧・矛盾している → 反映せず、追加の質問を出す。追加の質問の `対象:` に元の質問IDを書く(例: `対象: Q-012 の回答 / 03_BUC.md「予約を管理する」`)。元の質問は `回答済` のまま残し、追加の質問を `反映済` にするときに、元の質問も `反映済` にする。
- 反映できたら、質問の `状態:` を `反映済` にする。

**人の直接編集**ごとに:
- 人が書き換えた・追加した行は、出典を `回答` にする(人が `仮説` のまま残していても、内容を変えていれば `回答`)。質問列のIDが解決済みになるなら、その質問を `反映済` にする。
- 人が削除した行は、そのまま削除として受け入れる。

**追加資料**から:
- 既存の仮説の行を裏付ける記述があれば、出典を `資料:<ファイル名>` にし、紐付いた質問を `反映済` にする(質問の回答欄に「資料:<ファイル名> により確定」と書く)。
- 新しい要素は `資料:<ファイル名>` で追加する。既存の `回答` 行と矛盾する記述は、書き換えずに質問を出す。

### 3. 波及先を確認する

変更(書き換え・削除・名前変更)のあった要素を参照している行を、全ての表から探す。

- **名前の変更:** 参照している行の名前も揃える(機械的な追随なので出典は変えない)。
- **削除:** 参照している行は勝手に消さない。その行を `仮説` にし、「つなぎ替えるか削除するか」の質問を出す。
- **意味の変更**(例: アクターの担当範囲が変わった): 影響しそうな行を `仮説` に戻し、質問を出す。

どのフェーズの表でも同じように扱う。フェーズ番号は戻さない。

### 4. 追加の質問を出す

- 回答から新たに分かったこと、回答で生まれた新しい穴(`rdra.py check` の新しい指摘)を質問にする。
- 現在のフェーズの `checklist-phaseN.md` を当て直す。
- 優先度・高は1回あたり最大10問(`references/questions.md`)。

### 5. 仕上げ

1. コミットする(メッセージ `rdra: apply (Q-001〜Q-008 反映、追加質問 5件)`)。
2. 現在のフェーズに応じて `rdra.py gate 1|2|done` を実行し、結果を報告する。

## 完成処理

**完成は人の最終承認を得てから行う。** 判定を満たしても、AIが自分の判断で完成にしてはいけない。

完成の後に apply で表・質問を変えたときは、SKILL.md「完成の後に表・質問を書くとき」のとおり `rdra.py reopen` を先に実行している。完成に戻すのは下の手順だけ。

現在のフェーズが3で、`rdra.py gate done` を満たしたら、apply のコミットまでで止める。承認を求める前に `references/review.md` の手順でレビューを1回行う。優先度・高・中の質問が出たら、完成条件を満たさなくなったことを報告して止まる。質問が出なければ、判定を満たしたこと、優先度・低の残り、「許容」した項目を報告し、「完成にしてよいか」を尋ねる。承認を得たら:
1. `rdra.py diagrams`、`rdra.py analysis`、`rdra.py mark-done`、`rdra.py status` を実行する。
2. `rdra: 完成` としてコミットし、`git tag rdra-完成` を付ける(既にあれば `rdra-完成-2` のように番号を付ける)。
3. 完成にしたことを報告する。

ユーザーが完成を `--force <理由>` で指示したときは `rdra.py mark-done --force "<理由>"` を使う。

## チェック指摘の許容

ユーザーが「この指摘は問題ない」と判断したときだけ、`rdra.py accept <キー> "<理由>"` を実行する。AIの判断で許容しない。

## 報告

反映した質問のID、人の編集から `回答` にした行数、波及で仮説に戻した行数、追加した質問(優先度・高は件名)、判定の結果、次にやること。
