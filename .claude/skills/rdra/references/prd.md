# prd: 関係者MTG用のPRDを作る

目的: 非エンジニアを含む関係者と、今の要件定義の内容を読み合わせて議論する。MTGで出た意見は議事録として `inputs/` に戻し、apply で反映する。

## 手順

1. `rdra.py prd` を実行し、`docs/rdra/prd.html` を作る。中身は表・questions.md・初期要望.txt から機械的に作られる。**AIがPRDに文章を書き足したり、手で直したりしない。** 表現を変えたいときは表を直してから作り直す。
2. 作ったPRDを読み、MTGの前に気づいたことを報告する(PRDには書かない)。
   - 初期要望.txt の原文と、その後の決定が食い違う箇所(例: 初期要望にある機能を回答で不要にした)。初期要望.txt は人のファイルなので直さず、直すかどうかを尋ねる。
   - 優先度・高の未解決の質問。MTGで決めるべき論点として挙げる。
3. コミットする(メッセージ `rdra: prd 生成`)。

## PRDの構成

| 節 | 中身 | 元 |
|---|---|---|
| 目的と背景 | ゴールと達成の判断基準、続けて最重要要求・背景・スコープ外の原文 | 00_ゴール、初期要望.txt |
| アクターと外部システム | システムを中心にアクター・外部システムをつないだ図と、それぞれの説明 | 02_アクター |
| 要求 | 要求を「機能 / 非機能 / 方針(種別ポリシー)」に分け、見出しの下にそれぞれ何を入れるかを1行で示す | 01_要求 |
| 業務フロー | 先頭に、業務と関わるアクター・外部システムを線でつないだ図(向きなし。仮説の行でしか関わらない線は点線。業務が1つなら出さない)。続けて業務ごとに、BUCと関わるアクター・外部システムを線でつないだ図、業務の全アクティビティをアクターのレーンに置いて先・次のとおりに矢印でつないだ業務フロー図を出し、その下にBUCごとに、そのBUCのアクティビティだけの図(ほかのBUCとのつながりは「BUC「X」へ/から」で示す。5つ以上は縦並び)。アクター・外部システムはUC複合図と同じ形・色で描く。アクティビティごとの詳細はたたんで表示し、UCがあればUC複合図(画面・イベント・情報・条件・状態とのつながり。状態モデルはUCではなく持ち主の情報につなぎ、その線にこのUCで起きる遷移を書く。持ち主の情報をUCが扱っていなければ状態モデルは描かない。要素ごとに種類を書き、色で分ける。情報・条件・状態モデルは押すと中身を小窓に出す。情報の小窓には説明・コンテキスト・主な項目と、状態モデルの状態・バリエーションの値を出し、つながる情報や扱うUCは出さない。条件の小窓にも使うUCは出さない)で示す | 03_BUC |
| 情報 | 情報の関連を左から右にたどる図(矢印に多重度)と、コンテキストごとの表(主な項目、状態・バリエーションとその値、使うアクティビティ) | 04_情報 |
| 状態遷移 / 条件 | 状態モデルごとの状態遷移図(遷移UCが4つ以上なら「〜など N件」と縮める)、条件・バリエーション(あるときだけ)。条件の表がある条件は、説明の下に表を出す(軸が1つなら値と結果、2つなら縦横の表、3つ以上なら組合せの一覧。書かれていない組合せは「未定」) | 05_状態、06_条件 |
| これまでに決まったこと | 反映済の質問と回答 | questions.md |
| 議論したいこと | 未解決の質問(提案・理由・選択肢)と仮説の行 | questions.md、全表 |
| 議事メモ | 各項目のメモ欄をまとめてコピーする | — |

図は diagrams.md と同じ Mermaid で描き、prd.html は cdnjs の Mermaid で表示する(オフラインでは図の元の記述が文字で出る)。たたんだ欄の中の図は、開いたときに描く。

見出しにかっこ書きの言い換えを付けない。読み手に不要な生成元の説明(「docs/rdra の表から生成」「初期要望.txt」などのファイル名)は書かない。

見出しと本文は、RDRAの用語を言い換えずに使う(アクターと外部システム、要求、BUC、アクティビティ、UC、情報、コンテキスト、状態遷移、条件、バリエーション)。用語の意味は「この資料の読み方」の欄で説明する。出典のラベル(初期要望・決定など)、本文の質問番号「(Q-001)」、フェーズ名、要求ごとの「実現するBUC」は出さない。AIの仮説は図の点線と「議論したいこと」で示す。

## MTGのあと

人が「議事メモをコピー」でまとめたものを `docs/rdra/inputs/議事録_YYYYMMDD.md` に保存し、`/rdra apply` で追加資料として反映する。

## 報告

prd.html のパス、未解決の質問の数(優先度・高は件名)、MTG前に気づいた食い違い、MTG後の流れ(議事メモ → inputs → `/rdra apply`)を短く伝える。
