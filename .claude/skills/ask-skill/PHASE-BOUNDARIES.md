# フェーズ境界

**フェーズ**とは、セッション内の作業のまとまりのことだ。grilling、実装、QAなど。この定義はわざと曖昧にしてある。フェーズが終わるのは「よし、これで終わりだ」と思ったときだ。

**フェーズ境界**とは2つのフェーズの間の隙間であり、この決定が属する唯一の場所だ。フェーズの途中には決めることは何もない。続けるか、残った作業をサブエージェントに分割するかだけだ。フェーズの途中でコンパクトすると、エージェントは文脈の流れを見失う。

## 5つの選択肢

| 選択肢       | 何をするか                                                    |
| ------------ | --------------------------------------------------------------- |
| **継続** | セッションにとどまる。コンテキストの切り替えは一切なし。                    |
| **`/clear`** | コンテキストウィンドウを空にして、ゼロから始める。                  |
| **`/handoff`** | 持ち運び可能なMarkdownファイルを書き出し、どこでもそれを種にセッションを始められるようにする。 |
| **サブエージェント** | タスクを独自のコンテキストウィンドウに送り、レポートを受け取る。     |
| **`/compact`** | 現在のコンテキストを圧縮し、その要約を種に新しいセッションを始める。  |

## ツリー

境界では上から下へ順に検討する。最初の**イエス**が勝つ。

**1. このセッションで続けられるか?** 答えがイエスになる理由は2つある。次のフェーズが今のフェーズを**一次情報源**として必要とする場合、または次のフェーズが収まるだけの[スマートゾーン](https://www.aihero.dev/ai-coding-dictionary/smart-zone)(約15万トークン)が残っている場合だ。grillingから実装への移行は標準的なイエスのケースだ。実装は推論の要約ではなく、そのままの推論を欲しがる。継続にはコストがかからず、失うものもない。だから何よりも先にこれを検討して除外する。

**2. コンテキストは次にやることと無関係か?** このセッションにあるもの(探索、決定、行き止まり)はすべて使い捨てにできるか? もしそうなら**`/clear`**。これは盤上で最も安い手だ。時間もかからず、ウィンドウを丸ごと取り戻せる。`/clear`は終着点でもない。古いセッションは再開可能なままだ。

これを間違えたときのコストは一方通行だ。**関連のある**コンテキストをクリアしてしまうと、作ったものの背後にある**理由**を失い、差分を読み返してもそれは戻ってこない。

**3. 引き継ぐ必要はあるか?** `/handoff`は狭い用途向けだ。必要になるのは次の場合だけだ。

- **新しいハーネス**に切り替える(Claude → Codex)、
- 新しい**ディレクトリ**やリポジトリに移る、
- 作業を**同僚**に送る、
- または**フェーズの途中**で見つけた副次タスクを、今やっていることを脱線させずに分岐させる。

その一覧がすべてだ。`/handoff`が買っているのは**可搬性**だ。移動するファイル。何も移動しないなら、それは要らない。

**4. タスクは離席中にできるか?** 手を離れて放置しても、誘導なしで進められるくらい絞り込まれているか? それなら**サブエージェント**に送り、このセッションには手を触れない。自動化されたレビューが典型例だ。エージェントが差分を読んでレポートし、その間はあなたを必要としない。

**5. それ以外なら`/compact`。** 関連のあるコンテキスト、同じハーネス、同じディレクトリ、そして自分がループにとどまる必要がある場合。ツリーが行き着く先はここであり、頻繁にここに着地する。指示を渡す(`/compact we're going to QA this area`)ことで、要約が次のフェーズに必要なものを保つようにする。

`/compact`は**最初に手を伸ばすものではなく、デフォルト**だ。その上にある4つの問いはすべて、より安上がりか、より正確だ。人がここから始めてしまうときの失敗パターンは、要約が均してしまった決定について、新しいセッションが自信満々に間違ったことを言い出すことだ。

## 一次情報源と二次情報源

**継続**以外のすべての手は、**一次情報源**を**二次情報源**に変える。実際に起きたセッションが、その要約に置き換わる。トレードオフの形はいつも同じだ。

| 情報源                            | 情報量 | ノイズ | 動く余地 |
| --------------------------------- | ----------- | ----- | ------------ |
| 一次情報源(継続)                | 全部        | 多い  | 少ない       |
| 二次情報源(`/compact`、`/handoff`) | 劣化あり      | 少ない  | 多い       |

だから問い1が最初に来る。とどまるコストが得られるものを上回るときにだけ、この劣化の代償を払えばよい。

## これらは判断の問題だ

これらの問いは客観的なものではない。それぞれに好みが入り込む余地があり、同じ境界でも日によって答えが変わりうる。価値があるのは、これらを**作業の途中ではなく境界で**、**順番通りに**問うことにある。
