# Setup TS Deep Modules

このリポジトリのすべてのパッケージを**deep module**にする: 小さなインターフェースの裏に多くの振る舞いを持たせる。パッケージの公開面はその**エントリーポイント**(パッケージルートにあるファイル)であり、サブフォルダ内のものはすべて隠される。このスキルは[dependency-cruiser](https://github.com/sverweij/dependency-cruiser)と、エントリーポイントを唯一の入口にするルールをインストールし、そのルールが実際に機能することを証明する。

語彙(deep module、interface、seam、depth)については、Skillツールで「codebase-design」を呼び出し、その用語を一貫して使うこと。

## このスキルが強制する形

```
src/packages/
  <name>/
    index.ts        ← エントリーポイント(公開)。外部からはこれをインポートする。
    client.ts       ← 別のエントリーポイント。パッケージは複数公開してよい。
    lib/             ← 実装: 外部からは隠され、互いに自由にインポートできる。
    tests/           ← 併設されたテスト+フィクスチャ(サブフォルダなので非公開)。
```

公開面はパッケージの**ルートファイル**であり、指定された1つの`index.ts`ではない。慣習として実装は`lib/`に、テストは`tests/`に置かれ、すべてのパッケージが同じ2フォルダの形になる。ただしルール自体は一般的なもので、*どの*サブフォルダの中にある*何であれ*非公開になるため、フォルダを追加するために設定を拡張する必要は決してない。

4つのルールがあり、すべて`error`である:

1. **エントリーポイント境界**: パッケージ外のコード(アプリコードまたは別のパッケージ)は、そのパッケージのエントリーポイント(ルートファイル)のみをインポートでき、サブフォルダ内のものは決してインポートできない。
2. **パッケージ内の自由**: パッケージ自身のファイルは互いに自由にインポートし合える。
3. **エントリーポイントを通したテスト**: `<pkg>/tests/`配下のファイルは、任意のパッケージのエントリーポイントと自分自身の`tests/`フィクスチャをインポートできるが、どのパッケージのサブフォルダ内部も(自分自身のものでさえ)決してインポートできない。パッケージをまたぐ統合テストは問題ないが、深いインポートは許されない。
4. **循環禁止**: 依存の循環を禁止する。

**エントリーポイントであってバレルではない。** 公開面が*すべての*ルートファイルであるため、パッケージは1つの巨大な`index.ts`にすべてを詰め込むのではなく、複数の小さなエントリーポイント(`index.ts`、`client.ts`、`server.ts`)を公開できる。サブツリー全体を再エクスポートするバレルファイルは推奨されない。エントリーポイントは小さく保ち、実装はサブフォルダに隠すこと。

レイヤリング(どのパッケージがどのパッケージに依存してよいか)は*別の*関心事であり、このリポジトリで埋めるためのコメントアウトされたスタブとして設定内に残されている。

## 手順

### 1. 環境を検出する

- **パッケージマネージャ**: `pnpm-lock.yaml`→pnpm、`yarn.lock`→yarn、`bun.lockb`→bun、それ以外はnpm。以下のすべてのコマンドでこれを使う(`pnpm`/`yarn`/`npm run`/`bunx`)。
- **packagesルート**: `src/`が存在すれば`src/packages`を、なければ`packages`を使う。リポジトリに既に別の明白な慣習がある場合はユーザーに選択を確認する。
- **既存の設定**: `.dependency-cruiser.*`ファイルがないか確認する。存在する場合は**上書きせず**、4つのルールとオプションをマージし、追加した内容をユーザーに伝える。

**完了の条件:** パッケージマネージャ、packagesルート、既存設定の有無がすべて判明している。

### 2. dependency-cruiserをインストールする

検出したパッケージマネージャで`dependency-cruiser`をdevDependencyとしてインストールする。

**完了の条件:** `dependency-cruiser`が`devDependencies`に含まれている。

### 3. 設定を書き込む

[`dependency-cruiser.config.cjs`](./dependency-cruiser.config.cjs)をリポジトリルートに`.dependency-cruiser.cjs`としてコピーする。`PACKAGES_ROOT`をステップ1で検出したルートに設定する。ルールはパスの深さに基づいており拡張子に依存しないので、他に適応させるべきものはない。

**完了の条件:** `.dependency-cruiser.cjs`が正しい`PACKAGES_ROOT`とともに存在し、4つのforbiddenルールが含まれている。

### 4. チェックに組み込む

- `lint:boundaries`スクリプトを追加する: `depcruise <packages-root>`(または`depcruise src`)。
- 既に型チェックを実行しているリポジトリの統括チェックコマンド(`check`/`ci`/`validate`スクリプトなど)に組み込む。`tsconfig`には触れず、パスエイリアスも追加しないこと。
- 統括スクリプトが存在しない場合は`lint:boundaries`を追加し、CIに含めるようユーザーに伝える。

**完了の条件:** `lint:boundaries`が存在し、型チェックと同じコマンドの一部として実行される。

### 5. 例となるパッケージを足場として作る

コピー用テンプレートとして、コミットされた`<packages-root>/example/`を作成する。

- `index.ts`はエントリーポイントである。内部ファイルに委譲する1つの関数をエクスポートする(パッケージが単なる素通しではなく、目に見えて*deep*であるように)。
- `lib/impl.ts`: **サブフォルダ**内の内部ファイルで、`index.ts`からインポートされ、外部からは到達できない。
- `tests/example.test.ts`は**唯一**`../index`(エントリーポイント)をインポートし、公開関数に対してアサーションを行う。

これがコピーまたは削除してよいスターターテンプレートであることをユーザーに伝える。

**完了の条件:** 例となるパッケージが存在し、ルートのエントリーポイントを通して振る舞いを公開し、`impl`をサブフォルダに隠している。

### 6. ルールが実際に機能することを証明する

これがスキル全体の完了基準である: 違反で失敗しない設定には価値がない。

1. `lint:boundaries`を実行する。クリーンな例では**パス**しなければならない。
2. `tests/example.test.ts`に一時的に深いインポートを追加する(例: `import { thing } from "../lib/impl"`)。`lint:boundaries`を再度実行する。`tests-through-entrypoints`で**失敗**しなければならない。
3. 深いインポートを元に戻す。もう一度実行し、**パス**しなければならない。

**完了の条件:** パス、深いインポートでの失敗、再びパスという流れを実際に確認した。ステップ2で失敗しない場合、ルールが正しく組み込まれていないので、終える前に修正すること。

### 7. 慣習を文書化する

**packagesフォルダ内**(`<packages-root>/README.md`、それが統括するパッケージの隣)に`README.md`を書き、以下をカバーする: `src/packages/<name>/`のレイアウト(ルートにエントリーポイント、実装は`lib/`、テストは`tests/`)、「パッケージのエントリーポイント(ルートファイル)を通してのみインポートする」、`lint:boundaries`の実行方法。**バレルファイルを明示的に非推奨とする**: サブツリー全体を1つのindexで再エクスポートする代わりに、複数の小さなエントリーポイントを公開する。コピー用のスニペットと、4つのルールをそれぞれ1段落ずつにまとめて簡潔にすること。

それから、リポジトリのエージェント指示ファイル(`CLAUDE.md`が存在すればそれ、なければ`AGENTS.md`。どちらもなければ`AGENTS.md`を作成する)からそこへの**コンテキストポインタ**を追加する。1行で十分である。例: `Packages are deep modules: see [src/packages/README.md](./src/packages/README.md) before adding or importing one.` これによって、エージェントが境界ルールにつまずく代わりに、それを発見できるようになる。

**完了の条件:** `<packages-root>/README.md`が存在してバレルを非推奨としており、リポジトリの`CLAUDE.md`/`AGENTS.md`がそこへリンクしている。

## 注記

- 設定の`$1`バックリファレンス(dependency-cruiserのグループマッチング)が、パッケージが自分自身の内部に到達できる一方で外部からはできないようにしている仕組みである。これをパッケージごとの個別ルールに平坦化しないこと。
- 公開か非公開かは**深さ**で決まる: パッケージのルートファイルはエントリーポイントであり、サブフォルダ内のものはすべて非公開である。慣習上のサブフォルダは`lib/`(実装)と`tests/`だが、ルールはそれらをハードコードしていない。どのサブフォルダも非公開なので、新しいフォルダを追加しても設定変更は不要である。エントリーポイントの追加は単にルートファイルを追加することである(バレル不要)。
- パッケージは**フラット**である: ルート直下の子は1階層のみ。パッケージの内部はどれだけ深くネストしてもよいが、パッケージが別のパッケージを含んではならない。
- `"type": "module"`のリポジトリでも設定の`module.exports`が動作するよう、(`.js`ではなく)`.cjs`を使う。
