# GLOSSARY.md Format

`GLOSSARY.md`はこの教育ワークスペースの標準言語である。すべての解説、演習、学習記録はその用語に従うべきである。それを構築すること自体が学習の一部である。概念を凝縮した定義に落とし込むことは、ユーザーがそれを理解している証拠だからだ。

## 構造

```md
# {トピック} Glossary

{この用語集がカバーするトピックの1〜2文の説明。}

## Terms

**Hypertrophy**:
繰り返しのトレーニングセッションを通じて、機械的張力と代謝的ストレスによって引き起こされる筋肥大。
_Avoid_: Bulking、getting big

**Progressive overload**:
負荷、ボリューム、強度を通じて、筋への要求を時間とともに体系的に増やしていくこと。
_Avoid_: Pushing harder、levelling up

**RPE (Rate of Perceived Exertion)**:
そのセットがどれだけきつく感じたかを1〜10で自己評価するもの。10は限界、8はあと2レップ余裕があることを意味する。
_Avoid_: Effort score、intensity rating
```

## ルール

- **用語はユーザーが理解した時点で初めて追加する。** 用語集はユーザーが読んで学ぶための辞書ではなく、凝縮された知識の記録である。ユーザーがある概念に触れたばかりであれば、正しく使えるようになるまでここに昇格させるのを待つこと。
- **一貫した見解を持つ。** 同じ概念に複数の言葉が存在する場合、最良のものを1つ選び、残りは避けるべき別名として列挙する。これが言語を圧縮する方法である。
- **定義は簡潔に保つ。** 1〜2文。その用語が「何であるか」を定義し、「何をするか」「どうやるか」は定義しないこと。
- **用語集自身の用語を定義の中で使う。** ある用語が用語集に入ったら、他の定義の中も含めてあらゆる場所でそれを優先すること。これによって複雑な用語が後で理解しやすくなる。
- 自然なまとまりが生まれたときは**サブ見出しでグループ化する**(例: `## Anatomy`、`## Programming`)。用語がまとまっている場合はフラットなリストでもよい。
- **曖昧さは明示的に示す。** ある用語が広い分野で緩く使われている場合、解決策を書き留めること: 「このワークスペースでは、『set』は常にワーキングセットを指し、ウォームアップは別途扱う。」
- **理解が深まるにつれて改訂する。** 1週目にユーザーが書いた定義は、6週目には誤っているかもしれない。その場で更新し、古びたエントリを残さないこと。
