# 学習記録のフォーマット

学習記録は`./learning-records/`に置かれ、`0001-slug.md`、`0002-slug.md`のように連番で採番される。ディレクトリは遅延的に作成する。最初の記録が書かれるときだけでよい。

これらは教育版のADRである。今後のセッションを導く、非自明な教訓、重要な気づき、そして明言された既存知識を捉える。最近接発達領域を計算するために使われる。

## テンプレート

```md
# {学んだこと、あるいは確立された事柄の短いタイトル}

{1〜3文: 何が学ばれたか(あるいはどんな既存知識が確立されたか)、そしてそれが今後のセッションにとってなぜ重要か。}
```

これがフォーマットの全てである。学習記録は1段落だけでもよい。価値があるのは、_これ_が今や既知であることと、_なぜ_それが次に教えるべきことを変えるのかを記録することであって、セクションを埋めることではない。

## オプションのセクション

これらは本当に価値を加える場合にのみ含める。ほとんどの記録には不要である。

- **Status**フロントマター(`active | superseded by LR-NNNN`): 以前の理解が誤りだったと判明し置き換えられる場合に有用。
- **Evidence**: ユーザーがどのようにその理解を示したか(答えられた質問、完了した演習、引用された過去の経験)。その主張が後で見直される可能性がある場合に有用。
- **Implications**: これが今後のセッションで何を可能にし、何を排除するか。非自明な場合に記録する価値がある。

## 採番

`./learning-records/`をスキャンして既存の最大番号を見つけ、1つ増やす。

## 学習記録をいつ書くか

以下のいずれかが真であるときに書く。

1. **ユーザーが非自明な事柄について真の理解を示した**: 単なる接触ではなく、その概念を正しく使える証拠。これが次に教えるべきことの新しい底辺を設定する。
2. **ユーザーが既存知識を開示した**: 「Xはもう知っている」。今後のセッションが再度教えることのないよう記録する。主張された_深さ_も記録すること。
3. **誤解が訂正された**: ユーザーが以前は何か誤ったことを信じていて、今はなぜそれが誤りかを理解している。これらは高い価値を持つ。関連トピックで今後つまずきそうな箇所を予測させてくれる。
4. **学習に応じてミッションが変化した**: ユーザーは、自分が思っていたのとは違うことに関心があると気づいた。[[MISSION.md]]と相互リンクし、更新すること。

### 該当しないもの

- 単にカバーされただけの内容。カバーは学習ではない。証拠を待つこと。
- 用語定義として[[GLOSSARY.md]]に既に簡潔に記録されている事柄。重複させないこと。
- セッションごとの活動ログ。学習記録は日誌ではない。決定に値する洞察である。

## Supersession(上書き)

後の記録が以前の記録と矛盾する場合(ユーザーの理解が深まった、あるいは訂正された)、古い記録を削除するのではなく`Status: superseded by LR-NNNN`とマークすること。理解がどう発展してきたかの履歴そのものが有用なシグナルである。
